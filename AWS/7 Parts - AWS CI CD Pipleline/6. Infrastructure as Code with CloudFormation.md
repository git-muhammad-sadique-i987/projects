## Generating a CloudFormation Template

The IaC Generator is a tool in CloudFormation that helps make writing templates much, much faster.

It scans our AWS account, discovers all our resources, and generates the code for the resources we want to put in a CloudFormation template. This means we won't have to write code from scratch!

It works in a three step process where:

1. We scan all the resources in our AWS account

2. We create a template, which is a bundle of scanned resources that w'd like to deploy and manage together.

3. We import the template into CloudFormation to deploy the resources in one go.


A CloudFormation template lets us create and configure AWS resources (e.g. EC2 instances, CodeBuild projects, CodeArtifact repositories, etc.) as code instead of clicking around in the AWS console.

The resource that i could add to template include:

AWS::EC2::SecurityGroup
	
AWS::EC2::Subnet
	
AWS::EC2::Volume

AWS::EC2::VPC

The resources I could not add to my template were CodeBuild Project & CodeDeploy Deployment Group because the CloudFormation template struggles with resources requiring complex configurations.

## Template Testing

Before testing my template i deleted my CI/CD resources so that while template try to create a resource, there should not be any resource already in AWS account with the similar name. So if i do not delete my resources, my template will fail to run.

I tested my template by creating a new stack. The results of my first test was "ROLL_BACK_COMPLETE" because of following error message:

(Service: Iam, Status Code: 404, Request ID: 706c84c6-716e-42a2-bd6d-56b96c0605a6) (SDK Attempt Count: 1)" (RequestToken: ee8eaac0-8da2-9c2d-2f5f-9a208c8b7d28, HandlerErrorCode: NotFound)

## DependsOn

To resolve the error, I added the following line under "IAMManagedPolicyPolicyserviceroleCodeBuildCodeConnectionsSourceCredentialsPolicynextworkdevopscicduseast1619071326582:"

 DependsOn: "codebuild-nextwork-devops-cicd-service-role"

It would make the policy dependent on creation of role. The policy creation will wait until the required role is created. 

The DependsOn line was added to four different parts of my template:
IAMManagedPolicyPolicyserviceroleCodeBuild

IAMManagedPolicyPolicyserviceroleCodeBuildCloudWatchLogsPolicynextworkdevopscicduseast1

IAMManagedPolicyPolicyserviceroleCodeBuildBasePolicynextworkdevopscicduseast1

For CodeArtifact policy under following section
IAMManagedPolicyPolicycodeartifactnextworkconsumerpolicy

I added following lines:

DependsOn:
      - "codebuild-nextwork-devops-cicd-service-role"
      - "IAMRoleEC2instancenextworkcicd"

## Circular Dependencies

'I gave my CloudFormation template another test! But this time it said that my template had a circular dependencies. Meaning that policies are roles are dependent on each other for creation, so non of those creates and the loop goes on.  

To fix this error,  deleted ManagedPolicyArns as they were creating circular dependency.

## Manual Additions

In a project extension, I manually defined two more resources:
CodeBuild Project & CodeDeploy Deployment Group


I also had to make sure the references were consistent in this template, so I edited value inside placeholder in following blocks:
DependsOn:
      - "<YOUR_CODEBUILD_SERVICE_ROLE_ID>"
      - "<YOUR_S3_BUCKET_ID>"

Source:
        Type: GITHUB
        Location: !Sub "https://github.com/${GitHubRepoOwner}/${GitHubRepo}"
        BuildSpec: buildspec.yml
      Artifacts:
        Type: S3
        Name: nextwork-web-build.zip
        Packaging: ZIP
        Location: !Ref <YOUR_S3_BUCKET_ID>

ServiceRole: !GetAtt <YOUR_CODEBUILD_SERVICE_ROLE_ID>.Arn


I also introduced Parameters, which are

GitHubRepoOwner and GitHubRepo

Parameters make your CloudFormation template reusable and flexible. Instead of hardcoding values like GitHub usernames, you can parameterize them. This lets you use the same template for different environments or repositories without modifying the template itself.
